# claude-update: обновить Claude Code кнопкой

<img src="icon.svg" width="256" alt="Обновить Claude Code">

Плагин для [Agents Hub](https://github.com/flagman/agents-hub-core). Вкладка «Настройки» → «Claude Code» показывает,
какая версия Claude Code стоит, какая доступна и как claude поставлен на этой машине. Кнопка «Обновить» ставит новую
версию тем же способом:

- установщик Claude Code (`~/.local/share/claude/versions`): `claude update`;
- npm: `npm install -g @anthropic-ai/claude-code@<канал>` из той же папки, где стоит claude;
- Homebrew: `brew upgrade --cask claude-code`.

Потом плагин пишет хаб-сессии, чтобы она перезапустила хаб, когда сессии свободны (`hub restart`). Сам плагин весь
хаб перезапустить не может. Сессии работают на старой версии, пока хаб не перезапустится. Вкладка показывает, какие
сессии запущены раньше, чем поставлена нынешняя версия, и даёт кнопку «Перезапустить хаб».

Автоматики нет: обновление только по нажатию, с подтверждением.

Доступную версию плагин берёт из реестра npm, канал — `autoUpdatesChannel` из настроек Claude Code (`latest` по
умолчанию или `stable`). Claude — тот же, что запускает хаб: `HUB_CLAUDE` или первый `claude` в PATH.

## Аккаунт Claude и вход

Ниже версий - блок «Аккаунт Claude»: кто вошёл (почта, план), до какого числа действует вход и в каком он состоянии:
в порядке, истекает скоро (7 дней и меньше), вход слетел. Данные - из `claude auth status --json` того же claude, что
у хаба. `auth status` слёт входа сам не видит (токен лежит, а обновить его нельзя), поэтому «слетел» плагин определяет
по сессиям: последний ход сессии кончился ошибкой входа («OAuth session expired and could not be refreshed»,
`authentication_failed`, «Please run /login») не больше суток назад. Эти сессии вкладка перечисляет.

«Войти заново» ведёт вход через поток самого хаба (`/api/setup`, тот же, что в «Настройки» → «Setup»): страница
показывает ссылку «Открыть страницу входа» и поле для кода (с телефона код вставляется сюда), «Отмена» и «Проверяю
вход…». Когда вход выполнен, плагин один раз пишет каждой сессии, упавшей на ошибке входа, «продолжи»; перезапуск
хаба не нужен, сессии подхватывают вход сами. Если ядро не отдаёт `/api/setup` (старое), вкладка показывает
«Войди в терминале: claude auth login» и остальное не ломает. Если `claude` не сообщает срок входа, вкладка пишет
«срок Claude не сообщает».

Вход по токену. Если claude берёт `CLAUDE_CODE_OAUTH_TOKEN` (например, из `env` в `settings.json` профиля, откуда хаб
кладёт его и в сессии), `auth status` не сообщает ни почту, ни план, ни срок. Тогда вкладка берёт почту и план из
`oauthAccount` файла `.claude.json` того же профиля (читаются только эти поля) и помечает, что это запись последнего
входа в браузере, а токен может быть от другого аккаунта. Нет и этого - «вход по токену, почту Claude не сообщает».
Токен главнее входа в браузере, поэтому «Войти заново» сессии на токене не поправит: вкладка так и пишет, кнопка
называется «Войти на этом Mac», «продолжи» упавшим сессиям после такого входа не рассылается. Если у хаба включён пул
аккаунтов, вкладка показывает активный аккаунт пула по снимку страницы.

Несколько хабов на одном Mac обычно делят один claude. Обновили из одного хаба — у другого вкладка покажет его сессии
на старой версии и кнопку «Перезапустить хаб».

## Установка

«Настройки» → «Плагины» → поставить из маркетплейса. Без маркетплейса — строкой в `hub.json`:

```json
"extensions": {"claude-update": {"path": "~/hub-plugin-claude-update", "web": "web/main.js", "run": ["python3", "main.py"]}}
```

У плагина есть процесс (`main.py`): он узнаёт версии и запускает обновление. Страница говорит с ним по HTTP на порту
страницы + 11 (у страницы на 8787 — 8798), только со своей страницы. Нужен API плагинов хаба 1.7 или новее.
